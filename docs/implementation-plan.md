## Phase 2 — Educational engine (Days 1–2)
Pure Dart package `src/engine` (`bousla_engine`), no Flutter or Firebase dependency.
1. Models (matching `architecture.md` §3 and §5).
2. Scoring by option ID and question version.
3. Mastery estimation with insufficient-evidence states (thresholds in `architecture.md` §8; test the boundaries).
4. Prerequisite analysis (possible gaps only; otherwise "needs more evidence").
5. Class aggregates with the small-group threshold.
6. Resource recommendation (approved only; preferred language first).
Deliverable: unit tests for boundaries, empty input, unknown IDs, identical results in AR and EN.

## Phase 7 — AI level 2: explanations on top of the engine (Day 5)

- Template fallback on model failure or guard failure; "AI-generated" label next to the evidence.
- Evaluation: ~20 synthetic evidence cases in AR and EN; report the real guard pass rate.
Deliverable: grounded, guarded, measured AI explanations.

Status (24 Nov, student explanations): **implemented with guards and template fallback; verified with unit tests and a fake model only. Not yet run against Gemini; the ~20-case evaluation and the instructor teaching suggestion are not done.**
- Engine (`src/engine/lib/src/ai/feedback_explanation.dart`, pure Dart, exported from `bousla_engine.dart`): anonymous profile per student (concept names and states, student-facing prerequisite signals, recommendations with approved resource IDs and titles; no UID, name, answers, counts or URLs), identical profiles merged (`groupProfiles`, IDs `p1…` independent of student order), one prompt + JSON schema (array of `{profile_id, text_ar, text_en}`, 2–4 sentences, ≤ 600 characters), parsing, five guards and a deterministic bilingual template. `stripCodeFence` moved from `question_drafting.dart` to `ai/model_json.dart` (shared, behaviour unchanged).
- Guards (each a public function with its own tests): 1 concepts — no other course concept named (AR/EN, either text, article/prefix-tolerant, "Key" inside "Primary Key" not counted) and no foreign concept/resource ID; 2 resources — every link must be a profile resource URL, no unknown `res_…` ID, no title of another course resource; 3 language — `text_ar` has Arabic letters and at least half its letters Arabic, `text_en` has none; 4 wording — Arabic and English lists of definitive/judgmental phrases (e.g. لديك فجوة، لا تفهم، مستواك ضعيف، you have a gap, you failed, weak, definitely), matched after normalising diacritics, hamza and case; 5 length — non-empty, ≤ 600 characters. Any failure, a missing entry or an unreadable answer → that profile gets the template.
